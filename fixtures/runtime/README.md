# Runtime test fixtures

Synthetic videos used for **runtime-complete** verification of the autonomous
video→event pipeline. Both are real H.264 MP4 files encoded with ffmpeg
(`libx264`, 640×360, 12 fps) and analyzed by the real backend pipeline
(`backend.analysis.events.analyze_video_events`, which shells out to ffmpeg).

## door_open_18_4.mp4
- 20.0 s. Static room; a bright metal door panel (≈40% frame width) slides
  open at **t = 18.4 s** over ~0.75 s.
- Expected: one DOOR event, no motion elsewhere.
- Observed (fps=8, max_frames=280): `door` at **18.375 s**, conf 0.81,
  query `metal door hinge creak basement` → timing error **−25 ms**.

## five_footsteps.mp4
- 4.75 s. 0.8 s static lead-in; a large figure takes **5 steps** (0.8 s
  apart, each a smooth forward glide) starting at t = 0.8 s.
- Expected detections: 0.8, 1.6, 2.4, 3.2, 4.0 s.
- Observed (fps=12, max_frames=280): footstep at
  **0.833 / 1.667 / 2.417 / 3.250 / 4.000 s**, conf ≥ 0.81
  (`concrete single footstep basement`); MAX |error| = **67 ms**
  (within the 80–150 ms tolerance), plus one ROOM_TONE bed at 0.833 s.

## Regenerating
Both files are generated by tiny numpy scripts (written to `/tmp/mkvid*.py`
during development). To regenerate deterministically, re-create the frame
sequences described above and encode with
`imageio.v2.mimsave(..., fps=12, codec='libx264', macro_block_size=1)`.
